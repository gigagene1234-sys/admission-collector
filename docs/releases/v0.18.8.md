# Admission Hub v0.18.8 — Idempotent WebView Surface

v0.18.8 is a stability repair for the Galaxy-device behavior reported after v0.18.7, where the app appears to repeatedly reload or terminate while entering the Jinhak flow.

## What changed

The v0.18.7 passive-browser repair still rewrote WebView surface settings from navigation lifecycle callbacks. The main WebView also began life while the provider field was ADIGA and therefore received the collector UA suffix before the Jinhak launch path switched the same WebView back to the stock Android WebView UA.

v0.18.8 removes that runtime churn:

- the main WebView uses the stock Android WebView user agent for its entire lifetime;
- Jinhak browser-surface configuration no longer changes the user agent;
- `onPageStarted` and `onPageFinished` no longer reconfigure the browser surface;
- browser-surface configuration is idempotent per WebView instance and only runs again on a real manual/batch mode transition or after WebView replacement;
- off-main-thread calls are posted to the main handler instead of directly touching WebView;
- configuration is skipped after Activity destruction/finish;
- WebView/cookie configuration is wrapped so an unexpected settings failure is recorded instead of terminating the Activity;
- cookie acceptance/flush is applied only on the first configuration of each WebView instance;
- the v0.18.7 manual-browser popup and `stopLoading()` protections remain.

## Jinhak scope

Authentication remains user-owned. Admission Hub does not auto-login, inject credentials, restore a Jinhak auth lease, or infer authentication from cookies.

The automation start gate remains the visible Susi storage page:

`/jh/high3/early/four-year-university/library`

After storage is armed, traversal remains application-card/report-only with same-card binding. Leaving storage/report scope returns the surface to passive mode without stopping the provider navigation.

## Evidence safety

Adiga remains the official source baseline. Jinhak remains user-viewed/provider-derived evidence and is not promoted to official evidence. Existing `relation=HOLD` and `probabilityInferred=false` safeguards remain unchanged.

## Verification status

CI validates the v0.18.8 source contract, all unit tests, version metadata, stable signer, and clean-rebuild reproducibility.

The reported Galaxy crash/reload symptom cannot be declared fixed from CI alone. A new Galaxy recording is still required. Device acceptance therefore remains `PENDING_V0188_REAL_GALAXY_RUN`.
