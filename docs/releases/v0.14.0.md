# Admission Hub v0.14.0 — Adiga Evidence + XLSX Transcript Import

## 목적

v0.13의 6장 원서 적정성 검토를 유지하면서 두 가지 미완료 지점을 보강합니다.

1. `공식 전형 연결 확인 필요`처럼 모호한 상태를 없애고, 어디가 자료에서 정확히 무엇이 연결되었고 무엇이 부족한지 전형·모집단위·연도 단위로 표시합니다.
2. 학생부/내 성적 입력에서 `.xlsx` 파일을 직접 선택하고 시트·헤더·열 연결을 검토한 뒤 저장할 수 있게 합니다.

## 어디가 통합 분석

- 대학 단위 공식자료와 원서 직접 연결 근거를 구분합니다.
- 원서 직접 연결은 기존 보수적 규칙을 그대로 사용합니다: **같은 공식 행** 또는 **동일 공식 표의 명시적 전형 구간**에서 전형과 모집단위가 함께 확인되어야 합니다.
- 모집단위 요약만 맞고 전형 정보가 없는 경우 `모집단위 후보 확인 · 전형 결합 근거 없음`처럼 구체적으로 표시합니다.
- 전형 표기는 확인되지만 모집단위가 같은 행/구간에 없으면 별도 상태로 표시합니다.
- 대학 단위 자료, 서로 다른 행의 전형/학과 언급, 유사 전형명은 자동으로 합치지 않습니다.
- 현재 전형 근거와 과거 입결 근거를 분리하며, 공식 참고값·산식·점수척도가 사용자 확인되기 전에는 기존과 같이 판정을 보류합니다.
- 어디가 자료와 진학사 예측자료의 의미를 합치지 않습니다.

## XLSX 학생부 가져오기

- Android 문서 선택기에서 `.xlsx`를 직접 선택합니다.
- 여러 시트를 읽고 사용할 시트를 고를 수 있습니다.
- 헤더 행을 자동 제안하지만 사용자가 직접 변경할 수 있습니다.
- 학년, 학기, 교과, 과목, 석차등급, 학점/이수단위, 성취도 열을 자동 제안하고 저장 전 직접 수정할 수 있습니다.
- 원본 표 일부를 미리보기로 표시합니다.
- 병합 셀은 **학년·학기 열에서 XLSX에 실제 병합 범위가 선언된 경우에만** 상단 값을 이어받습니다. 단순 빈칸을 임의로 앞 행 값으로 채우지 않습니다.
- 빈 석차등급은 0등급으로 바꾸지 않고 빈 값으로 유지합니다.
- 수식은 실행하지 않습니다. 파일에 저장된 캐시 결과만 읽을 수 있으며, 실제 가져오기에 사용된 수식 캐시 셀 수를 저장 전 다시 표시합니다.
- XLSX ZIP 경로, 외부 relationship, 압축 해제 크기, 행/열 수에 안전 한도를 적용합니다.
- 최종 저장 전에 과목 수, 등급 없는 과목 수, 가중평균, 수식 캐시 사용 수, 병합 학년/학기 보완 수를 확인합니다.

## 데이터 보존 및 보안

- 기존 6장 선택 슬롯은 외부 수집이나 XLSX 가져오기로 변경·재정렬하지 않습니다.
- 기존 SQLite는 DB version 10을 유지하며 새 XLSX 결과는 기존 성적 프로필 JSON 구조에 추가 메타데이터로 저장합니다. 데이터 삭제형 마이그레이션은 없습니다.
- 로그인 비밀번호·쿠키·세션 토큰을 새로 저장하거나 export하지 않습니다.
- 앱 삭제 없이 기존 서명 앱 위에 업데이트 설치하는 경로를 유지합니다.

## 검증 기준

- v0.13에서 고정한 수집/세션/캐노니컬 핵심 파일 해시 보존
- 어디가 직접 연결과 대학 단위 자료의 비승격 테스트
- XLSX 다중 시트/shared string/병합 셀/빈 등급/수식 캐시/중복 열/필수 열/ZIP traversal 테스트
- 전체 JVM 단위 테스트 무실패
- Android 35 debug APK 컴파일
- 동일 안정 서명 인증서 SHA-256 확인
- exact committed source clean rebuild + 재테스트

## 설치 후 기기 확인 항목

1. 기존 v0.13 데이터와 6장 슬롯이 유지되는지 확인
2. `내 성적 입력 / 가져오기` → `XLSX 파일 가져오기 · 시트/열 미리보기`에서 실제 학생부 XLSX 열기
3. 시트/헤더/열 자동 연결이 실제 파일 구조와 맞는지 확인
4. 등급이 없는 진로선택 과목이 빈칸으로 유지되는지 확인
5. 6장 원서 상세에서 어디가 연결 상태가 `전형`, `모집단위`, `같은 행/표 구간`, `과거 입결` 부족 항목으로 구체적으로 표시되는지 확인
6. 기존 어디가·진학사 세션과 수집 기능이 유지되는지 확인

기기 확인은 CI로 대체할 수 없으므로 release 검증 JSON에서는 `deviceAcceptance`를 `pending`으로 유지합니다.
