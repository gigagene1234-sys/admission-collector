# Admission Hub v0.16.9 — Stable Signer Recovery

## 실기기 설치 실패 증거

2026-09-09 Galaxy 화면 녹화에서 v0.16.8 APK 업데이트 시 Google Play Protect가 `기기 보호를 위해 앱 차단됨`으로 설치를 중단했고, 패키지 설치 관리자는 최종적으로 `앱이 설치되지 않음`을 표시했다.

이 화면만으로 서명 불일치를 단정할 수는 없다. 다만 v0.16.8 GitHub Actions 로그를 다시 감사한 결과, `Restore stable signing key` 단계가 실제로는 기존 암호화 keystore를 복원하지 않고 `keytool -genkeypair`로 새 keystore를 생성하고 있었다. 따라서 이전 설치본과 동일한 안정 서명자를 보장하지 못하는 빌드 회귀가 확인되었다.

## v0.16.9 수정

- v0.16.8의 event-driven high3 인증 제품 로직은 변경하지 않는다.
- `signing/admission-upload.keystore.enc`를 `ADMISSION_INGEST_TOKEN`으로 복호화해 기존 stable signing key를 복원한다.
- APK 서명자 SHA-256이 다음과 정확히 일치하지 않으면 CI를 실패시킨다.
  - `db6cd5efceda108657662d06f857e5f0277301cb6ab97a75c8a01994c96e4995`
- versionName `0.16.9`, versionCode `116900`으로 배포한다.
- clean rebuild 후에도 같은 서명자, 버전, 패키지명이 유지되는지 다시 검증한다.

## Evidence-Safe 정책 유지

- 어디가/대학 자료는 공식 근거다.
- 진학사는 사용자 계정에서 실제 열람한 추정/분석 자료다.
- `relation == HOLD` 또는 `probabilityInferred == false`이면 합격확률, 퍼센트, 안정/적정/소신 결론을 새로 만들지 않는다.

## 실기기 승인 조건

배포 성공과 실제 Galaxy 설치/수집 성공은 별도다. v0.16.9 승인 조건은 다음과 같다.

1. 기존 앱을 삭제하지 않은 상태에서 업데이트 설치가 완료된다.
2. Play Protect 또는 패키지 설치 관리자가 설치를 중단하지 않는다.
3. 앱 실행 후 진학사 인증이 high3 event-driven 흐름으로 진행된다.
4. `jinhakV0912ProtectedCoreVerified >= 1` 또는 동등한 v0.16.8/0.16.9 high3 verification 증거가 남는다.
5. `jinhakBatchStartCount >= 1`.
6. Jinhak records/successfulSnapshots/structured prediction evidence가 실제 증가한다.

실기기 증거가 없으면 위 조건은 PENDING으로 유지한다.
