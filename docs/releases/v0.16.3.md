# Admission Hub v0.16.3 — Jinhak High3 Recover

v0.16.3은 v0.16.2 실제 Galaxy 실행 결과를 기준으로 수정합니다.

## 실기기에서 확인된 v0.16.2 문제

v0.16.2는 고1·2 로그인 컨텍스트를 확실하게 차단했지만, 차단 순간 Jinhak 단계를 `jinhak-lower-grade-login-fenced`로 종료했습니다. 그 결과 통합 세션은 완료 상태가 되었지만 진학사 수집은 0건으로 끝났고, 사용자가 원한 고3·N수 수집 단계로 이어지지 않았습니다.

## v0.16.3 동작

고1·2 컨텍스트를 발견하면 더 이상 진학사 단계를 끝내지 않습니다.

1. 현재 로그인/리다이렉트 로딩을 중단하고 고1·2 UI는 계속 숨깁니다.
2. 기존 수집 target과 통합 세션을 보존합니다.
3. 진학사 고3·N수 보호경로 `/jh/high3/.../library`로 제한 복귀합니다.
4. 최대 2회의 자동 복구에서 보호경로 인증을 확인합니다.
5. 인증되면 기존 batch가 일시정지된 경우 같은 target에서 바로 재개합니다.
6. 아직 batch 시작 전의 통합 전환 단계라면 인증 직후 Jinhak `startBatch()`를 호출합니다.
7. 자동 복구 2회가 모두 실패하면 진학사 단계를 종료하지 않고 `JINHAK_HIGH3_LOGIN_GATE`에 남깁니다. 고1·2 UI는 노출하지 않고 고3·N수 인증만 기다립니다.
8. 사용자가 기존 `로그인/동의 후 계속`을 누르면 고1·2 페이지를 여는 대신 고3 보호경로에서 bounded recovery를 새로 시작합니다.

## v0.16.2 회귀 제거

다음 terminal 동작은 제거했습니다.

- `finishBatch("jinhak-lower-grade-login-fenced")`
- `finishUnifiedCollection("jinhak-lower-grade-login-fenced")`

따라서 lower-grade 차단 자체가 Jinhak 수집 0건 종료의 직접 원인이 되지 않습니다.

## 데이터 정책

- 어디가/대학 입학처: 공식 현재 기준 및 공식 과거 입결
- 진학사: 사용자 계정에서 실제 열람 가능한 파생 분석/예측
- 진학사 미수집·로그인 실패를 공식 데이터로 보정하지 않음
- 사용자 고정 6장 자동 변경 없음
- 과거 입결 결합 조건 완화 없음
- `probabilityInferred=false` 유지
- HOLD 상태에서 합격확률 또는 안정/적정/소신을 생성하지 않음

## 실기기 승인 조건

CI 통과 뒤 실제 Galaxy에서 다음을 확인해야 합니다.

1. 고1·2 컨텍스트 감지 후 세션 `completionReason`이 즉시 lower-grade fence로 끝나지 않는지
2. 고3·N수 보호경로로 자동 복귀하는지
3. 인증 성공 후 상단 상태가 `수집 대기`에서 실제 Jinhak batch로 넘어가는지
4. `jinhakBatchStartCount >= 1`인지
5. Jinhak 페이지/레코드 또는 분석 capture가 실제로 증가하는지
6. 인증이 안 되더라도 고1·2 반복 진입 없이 `JINHAK_HIGH3_LOGIN_GATE`에 bounded 상태로 남는지
7. 어디가 공식자료와 기존 학생부/공식 근거가 유지되는지
