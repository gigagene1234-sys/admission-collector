# Admission Hub v0.17.2 — Screen-Recording Bootstrap Fix

## Why this release exists

A real Galaxy screen recording of v0.17.1 showed that manual Jinhak login itself completed successfully in the visible WebView. The failure happened immediately after the user pressed the explicit login-complete button: v0.17.1 replayed the protected `four-year-university/library` target that had caused the pause, the site returned that direct request to the member login surface, and the app re-entered the user-session gate.

The matching v0.17.1 export showed the same pattern: zero Jinhak mission actions/records, repeated user-session gates and confirmations, server login redirects, and the current target set to the protected library route.

## v0.17.2 behavior

- Jinhak authentication/session authority remains entirely with the user.
- Collector still does **not** verify Jinhak login, restore/capture a Jinhak auth lease, extend the session, read credentials, submit credentials, or export cookies/session secrets.
- After explicit user confirmation, exploration begins from the current public high3 four-year-university search surface rather than immediately replaying a protected report/library route.
- `four-year-university/library` remains a protected mission target; it is no longer the first bootstrap surface.
- If a protected target returns to a login surface after the user already confirmed the session, Admission Hub preserves the user's session assertion, defers that target for the immediate cycle, clears the stale `currentBatchTarget`, and returns to the public high3 bootstrap instead of asking the user to confirm the same login again.
- The same redirecting protected target is marked consumed/deferred so it cannot be immediately re-enqueued by discovery.
- Unknown/high3 exploration and the hard high1/high2/high12 transport fence are retained.
- The expanded dashboard browser introduced in v0.17.1 remains unchanged: always visible under the dashboard, minimum 720dp and approximately 68% of device screen height.

## Added diagnostics

Only non-secret counters/safe paths are exported:

- `v0172BootstrapStarts`
- `v0172ProtectedRetryDeferrals`
- `v0172LoginRedirectLoopBreaks`
- `v0172DeferredProtectedTargets`

No ID, password, cookie, token, form value, or session secret is exported.

## Admission evidence safety

This release changes navigation/session orchestration only. It does not promote Jinhak to an official source and does not infer admission probability. Official Adiga/university evidence remains separate from user-viewed Jinhak prediction/analysis evidence. Existing `relation`, `probabilityInferred`, `disclaimer`, `missing`, `warnings`, and `risks` safety contracts remain in force.

## Device acceptance

CI/source/APK verification can prove the route policy and regression contracts, but real-device acceptance remains pending until the updated APK is exercised on the Galaxy device. Acceptance requires: one manual login confirmation, no immediate confirmation→protected-target→login loop, bootstrap/search traversal after confirmation, and subsequent Jinhak mission/evidence progress without exposing authentication secrets.
