# Admission Hub v0.16.7 — Direct High3 Auth / No UI Mask

## 실기기 v0.16.6 증거

v0.16.6 unified export에서 진학사는 수집을 시작하지 못했다.

- phase: `jinhak`
- `jinhak.records = 0`
- `jinhakAnalysisCaptures = 0`
- `authVerifiedForBatch = false`
- `transitionAuthGateActive = true`
- `batchRunning = false`
- `loginRecoveryEpisodePolls = 164`
- configured max polls = 40, timeout = 60 seconds인데 `loginRecoveryFenceTrips = 0`
- credential submit은 1회 있었지만 success는 0

원인은 두 가지가 겹쳤다.

1. v0.16.6이 lower-grade 네트워크 요청을 차단하면서도 `WebView.visibility = INVISIBLE`, DOM `display:none`, `aria-hidden`, click suppression 같은 UI 조작을 계속 사용했다.
2. login recovery 제한이 `batchRunning && batchPausedForLogin`에만 적용되어, batch 시작 전 `transitionAuthGateActive` 상태에서는 재검증 poll이 제한 없이 계속될 수 있었다.

## v0.16.7 구조 변경

### 1. generic product login을 인증 bootstrap에서 제거

Collector는 더 이상 `https://www.jinhak.com/jh/member/login`을 인증 시작점으로 사용하지 않는다.

인증이 필요하면 identity-provider 회원 로그인에 명시적인 high3 ReturnURL을 붙여 진입한다.

`https://member.jinhak.com/MemberV3/MemberJoin/MemberLogIn.aspx?ReturnURL=<high3 target>`

ReturnURL은 반드시 `https://www.jinhak.com/jh/high3/...` 범위만 허용한다. lower-grade target은 high3 protected core로 정규화한다.

### 2. 고1·고2는 transport/navigation layer에서 drop

`/jh/high1`, `/jh/high2`, `/jh/high12` 및 이 경로가 nested redirect/query/fragment에 포함된 경우:

- main-frame request를 앱 내부 204 No Content로 응답한다.
- navigation override에서도 취소한다.
- 팝업이 해당 경로를 main WebView에 넘기지 못하게 한다.
- lower-grade 차단 함수는 WebView visibility를 변경하지 않는다.
- lower-grade 차단 함수는 `loadUrl()`을 호출하지 않는다.
- lower-grade 차단 뒤 자동 high3 recovery navigation을 예약하지 않는다.

즉 화면을 가리는 방식이 아니라 금지 목적지 자체를 수집기 navigation graph에서 끊는다.

### 3. DOM 학년 UI 조작 완전 제거

다음 구현을 제품 소스에서 제거했다.

- `installJinhakHigh3DomProductFence`
- 고1·2 selector `display:none`
- `aria-hidden` / `tabindex=-1`
- 고1·2 click `preventDefault` / `stopImmediatePropagation`
- 고3 tab 강제 click을 로그인 전제조건으로 사용하는 로직

학년 선택 UI의 모양이나 DOM 구조에 Collector 동작이 의존하지 않는다.

### 4. 로그인 대기는 passive state

identity-provider 로그인 화면에 들어간 뒤 Collector는:

- page를 숨기지 않는다.
- 보호경로를 반복해서 다시 열지 않는다.
- login recovery poll을 돌리지 않는다.
- 사용자가 사이트 로그인/Samsung Pass/자동완성을 끝내고 서버가 ReturnURL로 high3 페이지에 복귀하는 것을 기다린다.

high3 보호 페이지에 실제로 복귀한 뒤 `checkSessionState`가 authenticated && !needsLogin을 확인해야만 `authVerifiedForBatch=true`가 된다.

### 5. transition-auth 무한 poll 제거

기존 `pollJinhakLoginRecovery` 재귀 상태기계를 제거한다. `scheduleJinhakLoginRecovery`는 현재 route를 1회 분류하는 single-shot router만 남긴다.

따라서 batch 시작 전 transition auth에서도 `164 polls`와 같은 상태가 구조적으로 발생하지 않아야 한다.

## 진단값

v0.16.7 export에는 다음을 추가한다.

- `jinhakV0167CanonicalAuthEntries`
- `jinhakV0167GenericLoginRewrites`
- `jinhakV0167LowerGradeTransportDrops`
- `jinhakV0167AuthWaitEntries`
- `jinhakV0167AuthWaitDuplicateSuppressions`
- `jinhakV0167AuthExitsToHigh3`
- `jinhakV0167AuthWaitActive`
- `jinhakV0167AuthReturnTargetSafePath`
- `jinhakV0167GenericProductLoginBootstrap=false`
- `jinhakV0167DomGradeUiMask=false`
- `jinhakV0167RecursiveLoginPolling=false`

credential/password/cookie/token/form value는 export하지 않는다.

## Evidence-Safe 정책 유지

- 어디가/대학 자료: 공식 근거
- 진학사: 사용자 계정에서 실제 열람한 추정/분석 자료
- `relation == HOLD` 또는 `probabilityInferred == false`이면 합격확률이나 안정/적정/소신을 새로 만들지 않는다.

## 실기기 승인 조건

코드/CI/Release 완료와 실기기 승인은 분리한다. v0.16.7을 완전 해결로 승인하려면 실제 Galaxy에서 다음이 필요하다.

1. 고1·고2 화면이 한 번도 렌더링되지 않는다.
2. Collector가 generic `/jh/member/login`을 반복 bootstrap하지 않는다.
3. 로그인 필요 시 member.jinhak.com 회원 로그인 → high3 ReturnURL 흐름을 사용한다.
4. `loginRecoveryEpisodePolls`가 무한 증가하지 않는다.
5. `jinhakV0912ProtectedCoreVerified >= 1`.
6. `jinhakBatchStartCount >= 1`.
7. Jinhak records / successfulSnapshots / 구조화 prediction 중 하나 이상 실제 증가한다.
8. lower-grade transport drop이 발생해도 batch 전체를 종료하지 않는다.
9. credential/password/cookie/token/form value가 export되지 않는다.

이 증거 전에는 `진학사 로그인·수집 완전 해결`이라고 판정하지 않는다.
