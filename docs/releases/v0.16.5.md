# Admission Hub v0.16.5 — Login Handoff + Dashboard Gates

## 목적

v0.16.4 실기기 화면 녹화에서 진학사 실제 로그인 화면이 유지되는 동안 Collector의 로그인 진단/회복 루프가 계속 진행되고, 결국 `auth-probe-timeout`으로 종료되는 상태가 확인됐다. v0.16.5는 저장된 Collector 로그인 정보가 없는 경우 사이트 로그인 화면의 소유권을 사용자/기기 자동완성에 명시적으로 넘기고, 사이트 로그인 완료 후 protected high3 경로에서만 최종 인증을 승격한다.

## 로그인 단계 수정

- Collector-local credential이 없으면 진학사 로그인 화면을 안정적으로 유지한다.
- 로그인 화면에서 recovery가 보호경로를 반복 강제 탐색하지 않도록 manual-login gate를 둔다.
- 기기 자동완성/Samsung Pass 등 사이트 자체 로그인 수단을 그대로 사용할 수 있게 한다.
- `사이트 로그인·동의 완료 후 계속` 버튼은 현재 세션을 검사하고, 인증 증거가 있을 때만 protected high3 core로 handoff한다.
- protected high3에서 인증이 검증되면 독립 `실제 진학사 로그인 진단`도 즉시 성공 종료한다. 별도 timeout이 성공 뒤까지 남아 있지 않는다.
- 기존 v0.9.12 호환 passive redirect semantics, lower-grade post-auth fence, Jinhak→official 금지, credential/cookie export 금지는 유지한다.

## 대시보드 단계

대시보드는 다음 순서를 고정한다.

1. 진학사 로그인 확인
2. 진학사 수집 시작
3. 진학사 사용자 열람 자료
4. 어디가·대학 공식 근거
5. 공식 환산
6. 근거 안전 판단

각 단계에 `완료 조건`과 `현재 근거`를 표시한다. 지원 6장 카드에는 `relation`, `probabilityInferred`, `disclaimer`, `missing`, `warnings`, `risks`를 우선 노출하고, 이 값이 HOLD/비확률 모드를 요구하면 합격확률이나 안정/적정/소신을 새로 만들지 않는다.

## 출처 정책

- 어디가/대학: 공식 현재·과거 전형기준 및 공식 입시결과
- 진학사: 사용자 계정에서 실제 열람한 파생 분석·예측 자료

두 출처는 한 개의 합격확률로 합치지 않는다.

## 완료 판정

코드/CI/Release 성공과 실기기 승인은 별개다. v0.16.5 실기기 승인에는 최소한 다음이 필요하다.

- protected high3 인증 검증 1회 이상
- Jinhak batch 시작 1회 이상
- Jinhak records / successfulSnapshots / 구조화 예측 중 하나 이상 실제 증가
- 로그인 확인/수집 대기에 장시간 고착되지 않음
- credential/password/cookie/token/form value가 export되지 않음

실기기 증거 전에는 `진학사 로그인 해결 완료`라고 판정하지 않는다.
