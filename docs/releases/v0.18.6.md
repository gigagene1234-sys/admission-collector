# Admission Hub v0.18.6 — Manual Browser State Machine

v0.18.6 fixes the real-device regression observed in v0.18.5 where a successful user login could briefly reach the high3 search page and then be pushed back into the legacy authentication path.

## Three-state Jinhak runtime

Jinhak now has an explicit browser/runtime boundary:

1. `MANUAL_BROWSER` — before the protected Susi storage page is visible, Admission Hub is passive. The user may sign in with the provider/browser, use Samsung Pass, and navigate normally. Admission Hub does not stop loading, redirect, autofill credentials, probe authentication, restore an auth lease, or infer login success.
2. `STORAGE_ARMED` — the exact protected Susi storage route `/jh/high3/early/four-year-university/library` is visible. This is the only automatic start/re-arm signal.
3. `REPORT_TRAVERSAL` — after storage is armed, automation is limited to same-application-card report actions and read-only report routes under `/jh/high3/early/four-year-university/report/`.

If an active traversal leaves storage/report scope, the runtime uses `STOP_ONLY`: collection stops but the provider page is allowed to continue loading. No automatic login or route recovery is started.

## Removed active legacy auth behavior

Legacy compatibility functions remain only where required by the large existing activity surface, but their Jinhak behavior is inert. In particular, the active product does not use Jinhak credential autofill, a dedicated auth WebView, protected-session proof, real-auth probes, session keep-alive, or an authentication redirect loop.

Provider/browser cookies are not exported or cleared by this release. Authentication ownership is `user-browser-only`.

## Runtime version truth

The exported collector runtime version is now aligned with APK metadata: `0.18.6` / `118600`. This fixes v0.18.5 exports that could incorrectly identify the collector as 0.18.4 even though the installed APK metadata was 0.18.5.

## Exact local six-slot rebind

When the newest collection session has an empty/incomplete canonical graph but six user-pinned Hub slots already exist, v0.18.6 may reuse a prior local canonical session only if that session contains every pinned `applicationIdentityKey` exactly. It does not use university/department name similarity or cross-card inference.

The same exact canonical evidence session is used for the Hub candidate graph and score/application review. Review input is rebound to the exact selected identity and that candidate's academic year before evaluation, preventing an empty identity/year transport bug from manufacturing generic missing-evidence warnings.

## Evidence safety

Adiga remains the official current/historical baseline. Jinhak remains user-viewed/provider-derived analysis and prediction evidence. Prediction never overwrites historical actual results. Same-card binding remains mandatory. No acceptance probability or unsupported 안정/적정/소신 threshold is inferred.
