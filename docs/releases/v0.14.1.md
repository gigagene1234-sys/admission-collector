# Admission Hub v0.14.1 — Real XLS + Adiga Result/Score Fix

## Why this patch exists

The v0.14 device test exposed three concrete gaps that JVM fixtures did not catch:

1. The real student-record file is legacy Excel `.xls` (OLE2/BIFF8), while v0.14 only opened OOXML `.xlsx` ZIP files.
2. The canonical card stored only a bounded sample of Adiga diagnostic rows. A valid historical same-table binding could be counted but its actual row could fall outside that sample.
3. Official 2027 calculation tables were collected, but no evidence-scoped calculator materialized selected applications into `score_conversion_results`.

This release fixes those gaps without changing the six pinned application slots.

## Excel student-record import

- Accepts both `.xls` and `.xlsx` from Android's document picker.
- Detects the actual file format from bytes rather than trusting the extension.
- `.xls` is read locally with HSSF into the same review-first sheet/header/column-mapping model used by `.xlsx`.
- Formula expressions are never evaluated. Only saved cached results may be read.
- Blank grade cells remain null; they are never converted to grade 0.
- Real merged year/semester regions may fill structural values; ordinary blank cells are not forward-filled.
- File/row/column/merged-region limits remain enforced.

## Adiga official evidence and historical outcomes

- Keeps current 2027 direct binding distinct from separately verified official components.
- When the official site separates the admission-track table and recruitment-unit table, the UI now states that both components are officially confirmed without falsely claiming they were in one row.
- Known direct-binding counts remain visible even when the bounded card sample omitted the underlying row.
- Score/result materialization performs a full **local** rescan of the stored Adiga current/historical table records for only the user's selected applications; it does not revisit the network or read credentials.
- A historical result is stored only when:
  - the selected admission and recruitment unit are bound by the existing conservative same-row/explicit-same-table rule, and
  - the table headers actually identify 50%/70% result columns and the corresponding metric type.
- Change summaries or generic university tables are not promoted to admission results.
- Verified result values are surfaced on Hub cards instead of only showing a count.

## University score materialization

Automatic transcript score calculation is deliberately narrow and evidence-gated.

### Woosong University — 2027

Supported selected tracks:
- `교과면접`
- `교과중심`

The calculator uses the collected official 2027 course-selection, grade-average, career-subject bonus, and credit-bonus rules. It runs only after the official current admission component and recruitment-unit component are both confirmed and the user confirms the imported transcript is complete for the calculation.

### Hanbat National University — 2027

Supported selected tracks:
- `교과일반`
- `지역인재교과`

The calculator applies the collected official grade-point table, subject-group selection counts, department-group weights, career-subject scores, and eligible-credit weight. The automatically materialized value is explicitly labeled as the **academic-score component excluding attendance**; attendance is not invented from transcript grade rows.

### Korea National University of Transportation — 학생부종합Ⅱ

No deterministic transcript-grade score is invented. The current official evidence describes a document-based holistic evaluation, so the Hub shows that it is not a quantitative transcript-conversion target.

### Chungnam National University — selected `건축 / 교과일반`

Automatic conversion remains held because the collected selected-unit identity is not yet sufficiently specific for a safe official recruitment-unit binding. The patch does not guess between architecture-related official units.

## Comparison safety

- A separately verified scoring scope does not become a fake same-row application binding.
- Current converted scores and historical official outcomes are not compared unless their score scale and maximum are verified compatible.
- Historical 50%/70% values are stored and displayed even when cross-year scale equivalence has not been proven.
- No admission probability is inferred.
- No historical 2026 result is manufactured when the collected table is only a 2027-vs-2026 change summary.

## Data preservation

- SQLite DB version stays at 10.
- Existing selected six slots are read-only to the new materializer.
- No delete migration is introduced.
- Existing provider credentials/session-secret export boundaries remain unchanged.
- Update-install path with the stable signing certificate is retained.

## Device acceptance

CI verifies unit tests, Android compilation, package metadata, stable signer, exact committed-source rebuild, and regression contracts. Real `.xls` opening on the user's Galaxy device remains a device-acceptance item until the generated APK is installed and the actual file is selected.
