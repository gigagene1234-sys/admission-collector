# Admission Hub v0.18.4 — Single Surface Storage

v0.18.4 addresses the remaining Jinhak login handoff instability by removing the two-WebView authentication handoff from the active Jinhak path. Authentication and the protected Susi saved-application repository now run on the same foreground WebView.

## Jinhak runtime
- The Jinhak collector remains storage-only: `/jh/high3/early/four-year-university/library`.
- The same foreground WebView handles provider-owned login redirects and storage collection.
- `authWebView` is not used for the active Jinhak login path.
- If encrypted credentials are stored on-device, bounded autofill runs in the same foreground WebView. Manual login remains available.
- Login success is not inferred from a generic high3 page. Protected storage must render before the protected-session state is verified.
- Periodic competition refresh reuses/reloads the same storage WebView when possible.
- Competition observations remain Jinhak user-viewed derived evidence, not official evidence.

## Installed Jinhak application
The native Jinhak application is not used as an authentication bridge. Android app-private session state/cookies are not assumed to be transferable into Admission Hub's WebView without an explicit provider SSO/deep-link session contract. The release therefore avoids relying on an unverified cross-app session transfer.

## Adiga progress counters
Adiga intentionally reuses a stopped/incomplete provider run so hundreds of already-completed official pages can be preserved. Previously the UI displayed the current batch snapshot count next to persisted completion counts, which made a run with ~40 current attempts and 500+ persisted pages look impossible.

v0.18.4 separates these metrics in the UI and diagnostics:
- current-run screen/snapshot attempts,
- completed pages already present at batch start,
- newly completed pages during this batch,
- current cumulative completed pages.

This does not make Adiga processing faster; it makes run-resume reuse explicit.

## Evidence safety
- Adiga/university evidence remains official.
- Jinhak storage/competition observations remain user-viewed derived.
- Jinhak is never promoted to official evidence.
- HOLD and `probabilityInferred=false` behavior is unchanged.
- No acceptance probability or 안정/적정/소신 label is inferred from competition data.
- Credentials, cookies, form values, and session secrets are not exported.

Real Galaxy acceptance is still required before claiming the provider-side Jinhak login issue is fully resolved.
