# Admission Hub v0.18.7 — True Passive Manual Browser

v0.18.7 fixes the remaining real-device Jinhak regression reproduced after v0.18.6: the provider could briefly show the high3 university-search page and then return to the login page.

## Real-device finding

The v0.18.6 main WebView callbacks were passive before `/library`, but two lower-level browser surfaces were not fully aligned with that contract. The popup WebView bridge could still enter the legacy high3 sandbox independently of `batchRunning`, and the WebView surface retained collector-specific window/UA behavior. In addition, `stopBatch()` still called `webView.stopLoading()` for Jinhak, so a nominal STOP_ONLY scope departure was not literally stop-only.

## True passive manual-browser surface

Before the exact protected Susi storage route is visible and the report batch is armed:

- Jinhak uses the stock Android WebView user agent.
- Provider/browser cookies are accepted and flushed normally; they are never exported or interpreted as auth proof.
- Multiple-window and automatic-window collector behavior is disabled.
- The collector popup handoff is disabled.
- App-originated Jinhak navigation bypasses the legacy high3 route classifier while no batch is running.
- Main-frame request, navigation and SPA-history callbacks remain non-blocking.
- Admission Hub does not auto-login, inject credentials, infer authentication, restore a Jinhak auth lease, or force a route recovery.

## Storage and report traversal

The start gate remains exactly:

`/jh/high3/early/four-year-university/library`

Only after `startBatch()` is actually armed on that visible page may the report traversal surface enable its collector popup bridge. Navigation remains application-card/report-only and same-card binding remains mandatory.

If an active report traversal leaves storage/report scope, `stopBatch()` now switches Jinhak back to passive browser mode without calling `webView.stopLoading()`. The provider page is allowed to finish its own navigation.

## Existing Hub fixes retained

The v0.18.6 exact six-slot local rebind and application review identity/year propagation fixes are retained. Prior canonical evidence may be reused only when every pinned `applicationIdentityKey` matches exactly. No university/department name similarity or cross-card inference is used.

## Evidence safety

Adiga remains the official current/historical baseline. Jinhak remains user-viewed/provider-derived analysis and prediction evidence. Prediction does not become historical actual evidence. `relation=HOLD` and `probabilityInferred=false` continue to prevent unsupported acceptance probabilities or 안정/적정/소신 classifications.

CI verifies source contracts, unit tests, APK metadata, stable signer and clean-rebuild reproducibility. The Jinhak production login/storage flow still requires a new Galaxy real-device acceptance recording. Until that succeeds, device acceptance is `PENDING_V0187_REAL_GALAXY_RUN`.
