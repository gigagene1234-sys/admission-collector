# Admission Hub v0.19.0 — Jinhak Storage-Only Competition Monitor

This release replaces broad Jinhak traversal with one protected surface: the early-admission saved-application library.

## Jinhak collection scope
- Live collection target: `https://www.jinhak.com/jh/high3/early/four-year-university/library` only.
- Public high3 search, prediction reports, mock-support reports, actual-admit reports, score reports, strategy pages, media, regular-admission storage, and editorial routes are not autonomous collection targets.
- high1/high2/high12 transport remains blocked.

## Login architecture
- The collector loads the protected library directly.
- If Jinhak redirects to its login surface, that site-owned login remains visible in the SAME collector WebView.
- v0.19.0 does not divert that redirect into the legacy dedicated auth WebView.
- v0.19.0 does not read or submit a stored Jinhak credential and does not construct a member-login navigation.
- Collection resumes only after a natural return to the protected early-admission library.

## Competition monitor
- While a Jinhak collection run remains active, the protected library is refreshed every 15 minutes.
- The 15-minute interval is an Admission Hub product default, not a claim about Jinhak's server-side session TTL.
- Explicit `현재/실시간/원서접수 경쟁률` may be stored as current application competition.
- A current ratio may also be derived from explicitly current applicant count and explicitly labelled capacity on the SAME card.
- Generic unlabeled `경쟁률`, previous-year competition, and mock-support competition are never silently promoted to current application competition.
- Each accepted/unresolved observation is persisted as `jinhak-competition-snapshot` with observation time and Jinhak user-viewed provenance so changes can be tracked over time.

## Evidence safety
- Adiga/university evidence remains official.
- Jinhak competition and prediction observations remain user-viewed derived evidence and are marked non-official.
- This release does not infer acceptance probability and does not change HOLD behavior.
- `probabilityInferred=false` remains protected.
- Credentials, cookies, form values, and session secrets are not exported.

## Runtime scope
- The periodic refresh is an in-app/process-alive monitor using the authenticated WebView session. This release does not claim reliable Android background/Doze execution after the app process is killed.
