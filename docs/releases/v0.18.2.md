# Admission Hub v0.18.2 — Protected Session Bootstrap

v0.18.2 fixes the v0.18.1 false-positive Jinhak authentication state and the deterministic 60-second no-progress stop that followed it.

## Authentication semantics
- A public `/jh/high3/...` page is no longer authentication proof.
- `authVerifiedForBatch` becomes true only after the collector WebView actually finishes a protected saved-application or protected report route.
- A high3 return after login is only a handoff state: `HIGH3_RETURN_PENDING_PROTECTED`.
- Credential submit success is counted only after protected-core verification.
- Manual high3 return, credential submission, and protected-session verification have separate diagnostics.

## Dedicated login stability
- Only one autofill retry chain is allowed per auth generation.
- Form discovery remains bounded to 12 total attempts per generation; repeated `onPageFinished` callbacks cannot spawn overlapping chains.
- Protected-core probing is bounded to three 12-second attempts and returns to the dedicated auth surface when proof cannot be established.

## Six-application mission bootstrap
- The six pinned identities are activated before network collection.
- `prepareSelectedSixRecovery()` is run before protected mission collection so stale-but-pinned identities remain the local recovery scope.
- The protected saved-application surface is the required bootstrap boundary.

## Stall handling
- The generic 60-second Jinhak mission stall fence is disabled until protected-session proof exists and at least one concrete mission target has been created.
- Authentication/bootstrap failures use their own bounded state machine instead of being mislabeled as mission no-progress.

## Evidence policy
- Adiga/university evidence remains official.
- Jinhak remains user-viewed derived analysis/prediction and is never promoted to official evidence.
- HOLD / `probabilityInferred=false` behavior is unchanged.
- Credentials, cookies, form values, and session secrets are not exported.
