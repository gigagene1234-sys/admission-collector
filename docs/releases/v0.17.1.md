# Admission Hub v0.17.1 — User-Owned Jinhak Session + Expanded Browser

## Purpose

This release removes the Collector from the Jinhak authentication lifecycle. Jinhak login/session authority belongs entirely to the user and the site/WebView. Every Jinhak collection mission starts only after the user explicitly confirms that login is complete.

## Jinhak session contract

- Collector does not verify Jinhak login state.
- Collector does not restore or capture Jinhak auth-lease metadata.
- Collector does not read/store/submit Jinhak ID or password as part of collection startup.
- Collector does not extend the Jinhak session or click session-extension controls.
- Collector does not construct a Jinhak login URL.
- Collector does not treat a high3 page as authentication proof.
- Collector does not quarantine an admission target merely because the site redirected to login.
- If Jinhak presents a login surface during collection, the mission pauses and the browser is returned to the user unchanged.
- After the user presses **진학사 로그인 완료 · 탐색 시작/재개**, the Collector assumes login is complete and resumes the same mission without any second auth check.
- high1/high2/high12 routes remain transport-blocked as a separate grade-isolation safety contract.

`jinhakAuthVerifiedForBatch` remains only as an internal compatibility gate. In v0.17.1, `true` means **user-confirmed login assumption**, not Collector-verified authentication.

## Browser/UI change

The real site browser is no longer buried inside the collapsed advanced-tools area or limited to 320dp height.

- Browser is always placed directly below the main dashboard/decision summary.
- Width is full available width.
- Height is at least 720dp and otherwise 68% of the device screen height.
- Status text is shown directly above the browser.
- A dedicated user-session confirmation button is directly below the browser.

This is intended to make the full Jinhak login surface visible on Galaxy tablets without opening the advanced panel.

## Diagnostics

v0.17.1 exports the following non-secret state:

- `jinhakAuthModel = user-owned-session-login-assumed-v0171`
- `jinhakSessionAuthority = user`
- `userSessionConfirmed`
- `userSessionGateEntries`
- `userSessionConfirmations`
- `userSessionPauses`
- `collectorVerifiesLogin = false`
- `collectorRestoresJinhakAuthLease = false`
- `collectorCapturesJinhakAuthLease = false`
- `collectorExtendsJinhakSession = false`

Credentials, cookies, session secrets, tokens and form values are not exported.

## Admission evidence safety retained

- Adiga/university evidence remains official baseline/current-historical evidence.
- Jinhak remains user-viewed derived analysis/prediction evidence.
- Jinhak is never promoted to official evidence.
- Prediction does not overwrite historical actuals.
- Existing `relation`, `probabilityInferred`, disclaimer, missing/warnings/risks safety behavior is retained.

## Device acceptance

Build/CI success does not prove the real Jinhak session works on Galaxy. Device acceptance requires:

1. the expanded browser shows the complete Jinhak login/session page;
2. the app does not automatically navigate away from that page;
3. the user can log in manually and press the confirmation button;
4. Jinhak collection begins only after that confirmation;
5. no Collector auth probe/session-extension loop occurs;
6. if the site later returns to login, collection pauses for the user instead of opening a reauth circuit;
7. Jinhak mission/action/identity evidence actually increases.

Update-install over the existing app. Do not uninstall first because uninstalling may remove Admission Hub local data.
