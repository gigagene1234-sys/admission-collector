# Admission Hub v0.17.5 — Runtime-Stable High3 Sandbox

This release is a real-device stability correction for v0.17.4. The strict high3 transport fence remains fail-closed for lower-grade, shared-root, generic-login-router, and external collector navigation.

## What changed

- A blocked route is no longer treated as proof that the user logged out.
- Strict route rejection no longer clears the explicitly confirmed high3 session or pauses a healthy batch.
- The exact same-document SPA history alias `https://www.jinhak.com/jh/search` may be observed only after explicit high3 confirmation; it is **not** promoted to an allowed network/main-frame/collector destination.
- SPA history rejection no longer replaces the active page with `about:blank`.
- Snapshot overlap retry backoff is increased from 400 ms to 800 ms.
- First renderer-crash cooldown is increased from 2 s to 5 s.
- New exported diagnostics describe the v0.17.5 runtime contract.

## Security and evidence safeguards retained

- high1/high2/high12 remain blocked, including deeply encoded forms.
- generic `www.jinhak.com/jh/member/login` remains blocked as a collector route.
- member login is allowed only when the site-provided ReturnURL resolves to an allowed high3 target.
- credentials, cookies, and session secrets are not exported.
- Jinhak data remains user-viewed derived analysis/prediction and is never promoted to official Adiga evidence.
- The release does not infer admission probability; `probabilityInferred=false` remains the safety contract.

## Device acceptance

CI validates source, regression tests, clean rebuild, APK metadata, and stable signing. Real Galaxy acceptance remains pending until a new v0.17.5 unified export confirms that route blocks no longer flip `authVerifiedForBatch`/`batchPausedForLogin` during a valid high3 session and that renderer/snapshot recovery is stable.
