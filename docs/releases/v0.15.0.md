# Admission Hub v0.15.0 — Full Auto Evidence

## 목표
v0.14.2에서 실제 기기 사용 시 확인된 회귀를 수정합니다. 한 번의 자동 흐름이 어디가와 진학사의 로그인 상태를 모두 확인하고 두 공급자의 수집을 모두 수행하며, 수집 종료 시 선택 6장에 대해 어디가 공식근거 재연결·공식 과거 입결 저장·지원 대학 환산 재계산을 자동 수행합니다.

## 로그인·수집
- 앱 시작과 기본 수집 버튼 모두 `어디가 → 진학사` 인증 preflight를 수행합니다.
- 저장된 WebView 세션을 우선 검증하고, 실제 로그인 폼이 필요한 공급자만 기기 내부 암호화 계정을 사용합니다.
- 선택 6장의 기존 coverage가 완료되었다는 이유로 전체 수집을 생략하지 않습니다.
- 두 공급자는 동일한 자동 오케스트레이션 안에서 순차 실행됩니다. 단일 WebView 구조상 두 사이트의 네트워크 탐색을 같은 순간 병렬 실행한다고 표기하지 않습니다.
- 계정정보·쿠키는 GitHub Actions, Cloudflare, export JSON, 로그로 보내지 않습니다.

## 어디가 공식근거·입결
- canonical 카드에 보관된 제한된 표본만 보지 않고, 해당 unified session의 전체 로컬 어디가 레코드를 선택 6장 기준으로 다시 검색합니다.
- 전형·모집단위가 같은 행 또는 명시적인 동일 표 구간에서 확인될 때만 직접 결합으로 인정합니다.
- 지원년도 전형과 모집단위가 서로 다른 공식 표에서 각각 검증되는 경우에는 `공식확인`으로 표시하되 `직접결합`과 구분합니다.
- 과거 동일 전형·모집단위 행에서 헤더까지 검증된 50%/70% 환산점수·학생부등급만 공식 입결로 저장합니다.
- 수집 종료 후 이 재연결과 입결 materialization을 자동 실행합니다.

## 대학 환산점수
- 학생부 프로필이 존재하면 수집 종료와 Excel 저장 시점에 지원 대학 공식 산식 구현 범위에서 자동 재계산합니다.
- 정성평가 전형에는 정량 점수를 만들지 않습니다.
- 공식 산식이 구현·검증되지 않은 대학/전형은 HOLD를 유지합니다.

## XLS/XLSX
- 파일 인식 성공 즉시 인식된 과목을 `AUTO_RECOGNIZED_DRAFT`로 학생부 프로필에 저장합니다. 사용자가 화면 아래의 최종 버튼을 누르지 않았다는 이유만으로 Hub가 다시 0과목으로 표시되지 않습니다.
- 기존 고정 열 방식이 실패하면 학년/학기 표제가 섹션 행에 있고 과목 헤더가 학기별로 반복되는 학교 Excel 구조를 추가로 탐색합니다.
- XLS(OLE2/BIFF8), XLSX(OOXML) 모두 지원하고 빈 석차등급을 0으로 바꾸지 않으며 수식을 실행하지 않습니다.
- 최종 대학별 판단에 필요한 `학생부 전체 과목 누락 확인`은 사용자 확인 없이 임의로 true로 만들지 않습니다.

## 표시 변경
대시보드의 기존 `공식연결` 단일 수치를 다음처럼 분리합니다.
- `공식확인`: 지원년도 대학 공식자료에서 선택 모집단위와 선택 전형이 각각 검증된 카드 수
- `직접결합`: 전형과 모집단위가 같은 행/명시적 동일 표 구간에서 직접 연결된 카드 수

따라서 사이트 구조상 현재 전형표와 모집단위표가 분리된 경우에도 공식자료가 실제로 확인된 사실을 0/6으로 숨기지 않으면서, 직접 결합이 없다는 사실도 동시에 유지합니다.

## 안전 원칙
- `relation=HOLD` 또는 근거 미완성 상태에서 합격확률·안정/적정/소신을 새로 생성하지 않습니다.
- `probabilityInferred=false`를 유지합니다.
- 어디가 공식기준과 진학사 사용자 열람 기반 예측을 분리합니다.
- 기존 6장 슬롯은 자동 연결·Excel 입력 때문에 추가/삭제/재정렬하지 않습니다.

## 실기기 확인
CI 성공은 Android 실제 사이트와 실제 학생부 파일의 동작을 완전히 증명하지 않습니다. 업데이트 설치 후 실제 Galaxy 기기에서 (1) 어디가/진학사 자동 로그인 전환, (2) 두 공급자 자동 수집, (3) 실제 XLS/XLSX 과목 표시와 즉시 초안 저장, (4) 공식확인/직접결합/공식입결/대학환산 수치 갱신을 확인해야 합니다.
