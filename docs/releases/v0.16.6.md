# Admission Hub v0.16.6 — High3 Route Isolation

## 실기기에서 확인된 원인

v0.16.5 실기기에서 고3 로그인 뒤 고1·고2 계열 화면으로 잠깐 전환되고, 다시 고3 로그인으로 복귀하는 동작이 반복됐다. 화면 숨김 자체가 원인은 아니었다. 기존 v0.9.12 호환 코드가 `lowerGradeTransition`을 **숨겨진 인증 전환으로 허용**했고, 해당 전환에서 세션을 확인한 뒤 protected high3로 다시 넘기는 구조였기 때문에 고3 → 고1·2 → 고3 경로가 실제 상태기계에 존재했다.

또한 기존 `onPageStarted`는 진학사 로그인 URL 자체를 보이지 않게 만들 수 있었고, WebView renderer가 죽으면 현재 URL을 복구 대상으로 사용할 수 있어 금지 경로가 복구 후보로 다시 선택될 여지도 있었다.

## v0.16.6 변경

- 고1·고2·고1~2 경로는 UI 숨김이 아니라 **main-frame 네트워크 요청 단계에서 로컬 403 응답으로 차단**한다.
- `shouldOverrideUrlLoading`과 `onPageStarted`에도 동일한 하드 펜스를 적용한다.
- 팝업 WebView에도 같은 네트워크 하드 펜스를 적용한다.
- URL/query/fragment 안의 lower-grade return URL을 최대 3중 URL-encoding까지 해제해 차단한다.
- v0.9.12 호환 경로에서 lower-grade를 인증 전환으로 취급하던 로직을 제거한다.
- lower-grade 차단 1회당 protected high3 확인은 정확히 1회만 수행한다. 인증이 없으면 공유 로그인 화면으로 돌아오며 자동 재시도 루프를 만들지 않는다.
- 공유 진학사 로그인 페이지는 사용자 로그인용 정상 화면으로 항상 표시한다.
- protected high3 인증 뒤 재개 target이 lower-grade이면 해당 target을 다시 열지 않고 다음 수집 작업으로 진행한다.
- WebView renderer 복구 URL이 lower-grade이면 protected high3 core로 강제 정규화한다.
- 알려진 비핵심 lane은 계속 제외하지만, **새로 생긴/분류되지 않은 high3 URL은 단지 UI/page taxonomy가 미확인이라는 이유만으로 수집을 중단하지 않고 관측 대상으로 허용**한다.

## 안전 정책 유지

- 어디가/대학 자료는 공식 근거다.
- 진학사 자료는 사용자 계정에서 실제 열람된 추정/분석 자료다.
- `relation == HOLD` 또는 `probabilityInferred == false`인 항목에 합격확률이나 안정/적정/소신을 새로 만들지 않는다.
- credential/password/cookie/token/form value를 export하지 않는다.
- lower-grade 요청 차단은 수집 전체 종료 사유로 사용하지 않는다.

## 실기기 승인 조건

코드/CI/Release 성공과 실기기 승인은 별개다. v0.16.6 실기기 승인에는 최소한 다음이 필요하다.

1. 고3 로그인 후 고1·고2 화면이 한 번도 렌더링되지 않음.
2. `jinhakV0166LowerGradeRequestsIntercepted` 또는 `jinhakV0166LowerGradeNavigationsHardBlocked`가 증가하더라도 고1·고2 페이지 네트워크 이동을 따르지 않음.
3. protected high3 인증 검증 1회 이상.
4. `jinhakBatchStartCount >= 1`.
5. Jinhak records / successfulSnapshots / 구조화 예측 중 하나 이상 실제 증가.
6. lower-grade 차단이나 미분류 high3 페이지 때문에 전체 batch가 종료되지 않음.
7. credential/password/cookie/token/form value가 export되지 않음.

실기기 증거 전에는 `진학사 로그인·수집 완전 해결`이라고 판정하지 않는다.
