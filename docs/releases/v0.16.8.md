# Admission Hub v0.16.8 — Event-Driven High3 Auth

## 실기기 실패에서 확인된 문제

v0.16.6 실제 Galaxy 실행에서 진학사 인증은 transition auth gate에 머문 채 batch가 시작되지 않았고, 로그인 복구 poll이 설정된 상한보다 훨씬 많이 반복되었다. v0.16.7은 generic product login과 DOM 학년 가림을 제거했지만 추가 소스 감사에서 resumeAfterLogin, startup preflight, real auth probe, 저장 계정 로그인 후 검증 등 일부 레거시 인증 경로가 여전히 강제 navigation 또는 timer 기반 검증을 수행할 수 있음을 확인했다.

## v0.16.8 변경 원칙

진학사 인증은 navigation event만으로 진행한다.

1. `/jh/high1`, `/jh/high2`, `/jh/high12` 및 이 경로를 nested return/redirect target으로 포함한 main-frame 요청은 transport/navigation layer에서 drop한다.
2. lower-grade drop 함수는 WebView visibility를 변경하지 않고 `loadUrl()`도 호출하지 않는다.
3. generic `www.jinhak.com/jh/member/login`은 수집 bootstrap으로 쓰지 않는다. 필요 시 identity-provider 회원 로그인에 high3 ReturnURL을 붙여 한 번만 연다.
4. member login 화면에서는 passive wait 상태가 된다. 보호경로 재로드, polling, grade selector 조작을 하지 않는다.
5. 서버가 ReturnURL로 `/jh/high3/...`에 복귀한 navigation event가 발생한 뒤 실제 세션 검증이 성공해야만 수집 인증이 완료된다.
6. 미래의 새로운 high3 페이지는 UI taxonomy 미인식만으로 중단하지 않는다. high3 범위이면 인증 검증/관측 대상으로 유지한다.
7. `resumeAfterLogin`, startup preflight, transition auth gate, real-auth diagnostic, 저장 계정 자동입력 후속 동작을 같은 event-driven 규칙으로 통일한다.
8. 진학사에 대한 Collector 자체 credential dialog는 사용하지 않는다. 사이트 자체 로그인, 기기 자동완성, Samsung Pass를 사용한다.

## 정적 금지 조건

제품 소스에 다음이 남으면 release CI를 실패시킨다.

- `installJinhakHigh3DomProductFence`
- 고1·2 selector `display:none`
- `aria-hidden`, `tabindex=-1`, click suppression
- recursive `pollJinhakLoginRecovery`
- lower-grade hard-block 함수 내부 `loadUrl()` 또는 visibility mutation
- event-driven 인증 함수 내부 `WebView.visibility = INVISIBLE`

## Evidence-Safe 정책

- 어디가/대학 자료는 공식 근거다.
- 진학사는 사용자 계정에서 실제 열람한 추정/분석 자료다.
- `relation == HOLD` 또는 `probabilityInferred == false`이면 합격확률, 퍼센트, 안정/적정/소신 결론을 새로 만들지 않는다.

## 실기기 승인 조건

코드/CI/Release 완료와 실기기 승인은 별도다. v0.16.8을 실제 해결로 승인하려면 Galaxy에서 다음이 확인되어야 한다.

- 고1·고2 로그인/페이지가 렌더링되지 않는다.
- generic product login이 반복 bootstrap되지 않는다.
- 로그인 필요 시 member login → high3 ReturnURL 흐름만 사용한다.
- 인증 대기 중 recursive polling이 증가하지 않는다.
- `jinhakV0912ProtectedCoreVerified >= 1` 또는 동등한 v0.16.8 high3 verification 증거가 남는다.
- `jinhakBatchStartCount >= 1`.
- Jinhak records/successfulSnapshots/structured prediction evidence가 실제 증가한다.

실기기 증거가 없으면 위 조건은 PENDING으로 유지한다.
