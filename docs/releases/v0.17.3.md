# Admission Hub v0.17.3 — Natural High3 Handoff

## Why v0.17.2 still failed on the Galaxy recording

The v0.17.2 screen recording and exported diagnostics show a more specific race than the previous `/library` replay problem.

The visible flow is:

1. the Jinhak login form is used normally inside the app WebView;
2. the site briefly reaches a high3 university-search page;
3. the browser returns to the member login surface;
4. the same cycle repeats.

The matching v0.17.2 export shows that five of six v0.17.2 app-side session confirmations were recorded while the current safe path was still `/jh/member/login`. It also shows a second race: `v0171-login-surface` callbacks were processed after the currently-visible safe path had already become the high3 `/four-year-university/search` route. Those stale login callbacks revoked `jinhakUserSessionConfirmed` and put the batch back into a login pause.

The v0.17.2 bootstrap counters confirm that the previous mitigation did not catch this path: `v0172BootstrapStarts=5`, while `v0172LoginRedirectLoopBreaks=0` and `v0172ProtectedRetryDeferrals=0`.

## v0.17.3 behavior

v0.17.3 removes app-driven post-login bootstrap navigation from the handoff entirely.

- Pressing the Admission Hub session button while the visible Jinhak page is still a login surface **does not confirm a session and does not navigate anywhere**. It only arms a natural-resume state.
- The user completes Jinhak's own site login flow in the visible WebView.
- When Jinhak naturally returns to a high3 route, Admission Hub waits 900 ms and confirms that the same high3 route is still the current visible main-frame route.
- Only after that route-stability check does collection resume, and it resumes **in place from the already-visible high3 page**.
- A late `onPageFinished(login)` callback is ignored if the WebView is already visibly on a high3 route. It cannot revoke the high3 handoff.
- If a real login surface actually becomes current later, collection pauses and arms the natural handoff again. It does not bounce to `/search`, `/library`, or any other synthetic post-login URL.
- The hard high1/high2/high12 transport fence remains.

## Admission evidence safety

This release changes Jinhak browser/session orchestration only.

- Adiga/university evidence remains the official criteria/result layer.
- Jinhak remains user-viewed derived prediction/analysis evidence.
- Jinhak is not promoted to an official source.
- `relation`, `probabilityInferred`, `disclaimer`, `missing`, `warnings`, and `risks` safety contracts remain in force.
- This release does not infer an admission probability.

## Device acceptance

CI can verify source and APK contracts, but real-device acceptance remains pending until the Galaxy device is tested.

Acceptance requires:

1. pressing the app session button while `/jh/member/login` is visible causes no navigation;
2. completing Jinhak's own login naturally reaches and holds a high3 route;
3. a stale login callback cannot immediately send the app back into a login gate;
4. `v0173NaturalHigh3Resumes >= 1` after a stable natural high3 return;
5. `v0173AutoBootstrapNavigations == 0`;
6. Jinhak mission targets/actions/records or structured evidence begin to increase;
7. no authentication secret is exported.
