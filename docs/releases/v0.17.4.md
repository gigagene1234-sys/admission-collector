# Admission Hub v0.17.4 — Strict High3 Sandbox

## Scope

This release changes Jinhak browser/navigation orchestration only. It is designed to block not only the confirmed lower-grade loop path but every identified route family that could plausibly re-enter shared product routing or a lower-grade product.

## Strict visible main-frame policy

While the active provider is Jinhak, the visible top-level WebView is fail-closed. Only these top-level destinations are allowed:

1. `https://www.jinhak.com/jh/high3[/...]`
2. the exact HTTPS `member.jinhak.com/.../MemberLogIn.aspx` surface used by Jinhak for user-controlled login
3. `about:blank` as a neutral renderer placeholder

The following top-level destinations are blocked:

- `/jh/high1`, `/jh/high2`, `/jh/high12`
- lower-grade destinations nested inside query / fragment / ReturnURL material, including repeated URL encoding
- shared `https://www.jinhak.com/` root
- generic `https://www.jinhak.com/jh/member/login` product router
- non-high3 Jinhak product routes
- other `member.jinhak.com` top-level pages
- external top-level destinations
- non-HTTPS top-level destinations

## Defense in depth

The same rule is enforced at multiple layers so one missed callback is not enough to escape the sandbox:

- provider default URL is now a high3 route, never the shared root;
- adapter queue admission accepts high3 only;
- mission seeds and discovered URLs are filtered before queue insertion;
- Cloud frontier Jinhak tasks are filtered before queue insertion;
- `shouldInterceptRequest` blocks lower-grade markers for every request and fail-closes disallowed main-frame requests;
- `shouldOverrideUrlLoading` fail-closes disallowed main-frame navigation;
- `onPageStarted` stops forbidden history / POST / JavaScript / redirect navigation that reached the renderer;
- `onPageFinished` does not convert forbidden or login callbacks into auth success;
- Android WebView service-worker requests receive a lower-grade fence;
- popup/new-window handoff accepts only strict high3 or the exact member login surface;
- the Back button refuses history entries outside the sandbox;
- renderer recovery accepts only a validated high3 mission origin/target; otherwise it stays at `about:blank` and returns control to the user;
- persisted mission/current targets are revalidated before use;
- legacy auto-login recovery, legacy verified-auth resume and natural auto-high3 activation are disabled.

## User-owned login and exploration activation

Jinhak session authority remains with the user.

- Admission Hub does not read or submit Jinhak ID/PW.
- Admission Hub does not restore/capture a Jinhak auth lease.
- Admission Hub does not extend the Jinhak session.
- A member-login page is never considered collection-ready.
- Reaching high3 does not automatically start collection.
- The user must see a high3 page and explicitly press the Jinhak high3 exploration button.
- If the current page is neither strict high3 nor the exact member-login surface, pressing the button opens only the strict high3 entry URL.

## Admission evidence safety

This release does not change admissions conclusions.

- Adiga/university evidence remains the official criteria/result layer.
- Jinhak remains user-viewed derived prediction/analysis evidence.
- Jinhak is never promoted to official evidence.
- `relation`, `probabilityInferred`, `disclaimer`, `missing`, `warnings` and `risks` semantics remain in force.
- This release does not infer an admission probability.

## Device acceptance

CI can prove source and APK contracts but cannot prove Galaxy/Jinhak server behavior. Real-device acceptance remains pending until the installed build shows:

1. no visible high1/high2/high12 page;
2. no shared-root or generic-login-router top-level navigation;
3. lower-grade route attempts are blocked even from redirects, popups, history and service-worker traffic;
4. the exact member-login surface remains user-controlled;
5. high3 collection starts only after explicit user approval on a visible high3 page;
6. Jinhak mission targets/actions/records or structured evidence begin to increase;
7. no authentication secret is exported.

Update-install over the existing app. Do not uninstall first because uninstalling can remove local Admission Hub data.
