# Admission Hub v0.16.2 — Jinhak Fail-Closed Auth

v0.16.2는 v0.16.1 실제 Galaxy 화면 녹화에서 확인된 로그인 상태 머신 정체를 수정합니다.

## 실제 기기에서 확인된 문제

v0.16.1은 고1·2 로그인 컨텍스트를 화면에서 숨기는 데에는 성공했습니다. 그러나 로그인 DOM이 `safeHigh3=false`인 동안 `unsafe-login-recheck`를 500ms 간격으로 다시 실행했습니다. 결과적으로 사용자는 고1·2 페이지를 보지 않아도 상단 상태가 계속 `로그인 확인 중 · 진행 수집 대기`에 머물 수 있었습니다.

즉 문제는 화면 차단이 아니라 **차단 이후에도 인증 복구 상태 머신이 같은 로그인 페이지를 재시도한 것**입니다.

## v0.16.2 변경

- 공용 진학사 로그인 페이지에서 고1·2 컨텍스트가 안전하게 해소되지 않으면 해당 Jinhak 인증 시도를 즉시 terminal 상태로 전환합니다.
- `unsafe-login-recheck` 재귀 호출을 제거했습니다.
- lower-grade URL 직접 탐색/리다이렉트도 인증 중에는 같은 terminal fence로 종료합니다.
- terminal fence가 켜진 뒤에는 다음 콜백이 모두 no-op입니다.
  - login surface detector
  - saved credential auto-login
  - Jinhak login recovery
  - startup login poll
  - real auth probe poll
- WebView는 문제 로그인 페이지 로딩을 중단하고 `about:blank`로 이동합니다. 고1·2 로그인 화면을 다시 열지 않습니다.
- Jinhak 단계가 이미 batch 수집 중이면 `finishBatch("jinhak-lower-grade-login-fenced")`로 종료합니다.
- Jinhak transition/auth 단계라면 `finishUnifiedCollection("jinhak-lower-grade-login-fenced")`로 통합 세션을 마무리합니다.
- 어디가 공식자료, 학생부, 이미 저장된 공식 근거는 유지합니다.
- 다음 명시적 통합 수집을 시작할 때만 terminal latch를 초기화합니다.

따라서 이번 버전의 우선순위는 **진학사 로그인이 실패하더라도 앱 전체 실행이 로그인 대기 상태에서 무한 정지하지 않는 것**입니다.

## 입시 근거 정책 유지

- 어디가/대학 입학처: 공식 기준 및 공식 과거 입결
- 진학사: 사용자 계정에서 실제 열람 가능한 파생 예측·분석
- Jinhak 실패를 이유로 진학사 값을 공식자료로 승격하지 않음
- 과거 입결 binding 완화 없음
- 사용자 고정 6장 자동 변경 없음
- `probabilityInferred=false` 유지
- HOLD 상태에서 합격확률·안정/적정/소신을 새로 생성하지 않음

## 실기기 승인 조건

CI 통과 후 실제 Galaxy에서 다음을 확인합니다.

1. 고1·2 로그인 컨텍스트가 감지된 뒤 상태가 20초 이상 `로그인 확인 중`에 머물지 않는지
2. 같은 로그인 URL을 반복해서 재시도하지 않는지
3. 진학사 단계가 종료되어 통합 수집 최종화로 넘어가는지
4. 어디가 공식 입결/학생부 환산 결과가 보존되는지
5. 새 JSON에 `JINHAK_LOWER_GRADE_LOGIN_FENCED`와 `retrySuppressed=true`, `loginPageReopenAllowed=false`가 기록되는지
