# Admission Hub v0.15.1 — Wide XLS + High3 Fence

v0.15.1은 실제 Galaxy에서 확인된 두 가지 실사용 차단 문제를 우선 수정합니다.

## 1. 실제 학교 `학생부 성적 관리.xls` 형태 인식

기존 v0.15.0은 `학년/학기/과목`이 각각 열로 반복되는 표와 `1학년 → 1학기` 구간형 표를 인식했습니다. 실제 학교 내보내기 파일 중에는 한 과목 행 안에 다음처럼 두 학기 열 묶음이 함께 존재합니다.

- `학년`, `교과`, `과목`
- `1학기 단위수/학점`, `1학기 석차등급`, `1학기 성취도`, ...
- `2학기 단위수/학점`, `2학기 석차등급`, `2학기 성취도`, ...

v0.15.1은 `wide-semester-columns` 인식기를 추가해 한 물리 행을 실제 학기별 과목 행으로 분리합니다.

- 학년은 파일의 `학년` 셀에서만 읽습니다.
- 학기는 `1학기`/`2학기` 열 머리글에서만 읽습니다.
- 석차등급 `0`, 빈칸, `-`는 **등급 없음(null)** 으로 보존합니다.
- 진로선택 성취도와 파일에 존재하는 `성취도별분포(A~E)`도 근거 데이터로 보존합니다.
- 파일에서 명시되지 않은 학년·학기·등급·학점은 추측하지 않습니다.

## 2. 진학사 고3 세션을 고1·고2 제품으로부터 격리

v0.15.0 진단에서는 로그인 폼 제출 후 고3 보호경로 검증 중 세션이 반복해서 다시 로그인 대기로 돌아갈 수 있었습니다. v0.15.1에서는 인증/수집 중 아래 경로를 같은 진학사 도메인이더라도 차단합니다.

- `/jh/high1/`
- `/jh/high2/`
- `/jh/high12/`

차단은 메인 WebView 이동, 서버/스크립트 리다이렉트 보조 방어, 팝업 handoff 모두에 적용합니다. 차단 자체는 쿠키 삭제나 계정 재입력을 발생시키지 않습니다. 고3 보호경로와 회원 로그인 경로만 인증 흐름에 남깁니다.

실기기 export에는 `lowerGradeNavigationsBlocked` 카운터를 남겨 실제로 이 방어가 동작했는지 확인할 수 있습니다.

## 3. 진학사가 실패해도 어디가 공식자료 materialize 진행

신규 어디가 수집 세션에 공식 레코드가 충분히 있어도 같은 세션의 진학사 인증이 후보 그래프 생성 전에 실패하면, v0.15.0은 현재 세션 후보가 0개라는 이유로 공식 환산/과거 입결 결합도 0건이 될 수 있었습니다.

v0.15.1은 사용자에게 고정된 6개 `applicationIdentityKey`가 현재 세션 후보 그래프에서 보이지 않을 때 **직전 재사용 가능한 canonical 세션의 후보 메타데이터만** 가져옵니다. 이후 공식 근거는 반드시 **현재 세션의 어디가 레코드 전체를 다시 스캔**해서 결합합니다.

따라서:

- 이전 진학사 수치나 이전 어디가 공식값을 현재 공식값으로 복사하지 않습니다.
- 6장 선택 순서/내용을 자동 변경하지 않습니다.
- 과거 입결은 계속 동일 전형 + 동일/동등 모집단위 + 공식 표 헤더 검증 조건을 요구합니다.
- `probabilityInferred=false` 안전정책을 유지합니다.

## 출처 신뢰도

- 어디가: 공식 현재 기준·공식 과거 입결 baseline
- 진학사: 사용자 계정에서 실제로 열람 가능한 파생 분석·예측 자료

두 출처는 병합 저장하더라도 의미를 동일시하지 않습니다.

## 실기기 승인 조건

CI 성공은 실제 Galaxy 수용 테스트를 대체하지 않습니다. 업데이트 설치 후 다음을 확인해야 합니다.

1. 실제 `.xls`가 `wide-semester-columns`로 인식되어 학기별 과목이 표시되는지
2. 고3 로그인 후 고1·고2 화면으로 넘어가지 않는지
3. 통합 수집이 진학사 로그인 재시도 무한루프 없이 진행 또는 안전 종료되는지
4. 어디가 공식 환산/입결 materializer가 진학사 실패와 독립적으로 선택 6장을 처리하는지
