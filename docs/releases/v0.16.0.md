# Admission Hub v0.16.0 — Official Dashboard + Login Recovery

v0.16.0은 v0.15.1 실기기 export에서 확인된 세 가지 차단 문제를 수정합니다.

## 1. 학생부는 입력됐는데 대학 환산이 계속 보류되던 문제

학교 Excel이 이미 1학년 1학기부터 3학년 1학기까지의 학기 범위와 과목/학점을 구조적으로 포함하는 경우, 앱이 문서 구조 자체를 보수적으로 검증합니다.

- 필수 학기: 1-1, 1-2, 2-1, 2-2, 3-1
- 최소 과목 행 수와 과목명/학점 무결성을 함께 확인
- 파일에 없는 과목, 등급, 학점을 추측하지 않음
- 구조 검증이 성공하면 `documentCompletenessVerified=true`
- 사용자가 직접 전체성 확인을 체크한 경우도 계속 인정

이로써 정상 인식된 실제 학교 XLS에서 단순히 수동 체크가 false라는 이유만으로 우송대/한밭대 공식 환산 계산이 막히지 않습니다.

## 2. 어디가 공식자료 materialize를 진학사 로그인과 분리

v0.15.1 실기기 세션에서는 어디가 공식 레코드 18,609건이 저장됐지만 진학사 인증이 중간에 실패해 현재 canonical graph가 비었고, 공식 환산/입결 표시도 함께 가려질 수 있었습니다.

v0.16.0은 대시보드 갱신 시 최신 어디가 세션을 독립적으로 다시 materialize합니다.

- 현재 세션 어디가 레코드를 다시 스캔
- 현재 세션 후보가 비어 있으면 직전 재사용 가능한 canonical 세션에서 **후보 메타데이터만** 사용
- 이전 공식 수치나 이전 진학사 수치를 현재 수치로 복사하지 않음
- 사용자 고정 6장 순서/내용을 변경하지 않음
- 과거 입결의 전형/모집단위 결합 조건을 완화하지 않음
- `probabilityInferred=false` 유지

## 3. 진학사 로그인 무한 복구 차단

v0.15.1의 3회 재인증 상한은 `batchRunning=true`일 때만 적용되는 경로가 남아 있었습니다. 실제 기기에서는 transition login gate에서 `batchRunning=false`인 채 재인증 횟수가 5회까지 증가했습니다.

v0.16.0은 다음 상태에서도 동일한 3회 circuit breaker를 적용합니다.

- 일반 batch 수집
- 통합 수집
- transition auth gate
- 시작 시 로그인 preflight

고1/고2/high12 경로 차단도 그대로 유지합니다. 상한 도달 시 진학사만 안전 종료하고, 이미 확보한 어디가 공식자료는 보존합니다.

## 4. 전체 대시보드

새 `전체 대시보드` 화면을 추가했습니다. 6장 각각에 대해 다음을 분리 표시합니다.

- 대학 환산점수
- 어디가 공식 과거 입결
- 진학사 사용자 열람 예측
- 종합 판정/HOLD
- 공식 구성요소 연결 상태

상단에는 학생부 입력 상태와 파이프라인 요약을 표시하며 `공식 환산·입결 다시 계산` 버튼으로 저장된 공식자료를 즉시 재결합할 수 있습니다.

## 출처 정책

- **어디가:** 공식 현재 전형 기준 및 공식 과거 입결 baseline
- **진학사:** 사용자 계정에서 실제 열람 가능한 파생 분석·예측

두 출처는 같은 의미로 승격하지 않습니다. HOLD이거나 `probabilityInferred=false`인 항목에 합격확률을 새로 만들지 않습니다.

## 실기기 승인 조건

CI 성공은 실제 Galaxy 검증을 대체하지 않습니다. 업데이트 설치 후 다음을 확인해야 합니다.

1. 기존 입력 학생부가 유지되고 전체성 구조 검증이 적용되는지
2. 우송대/한밭대 지원안에 공식 환산 계산 결과 또는 명확한 HOLD 사유가 표시되는지
3. 어디가 공식 과거 입결이 결합 가능한 지원안에 표시되는지
4. 진학사 로그인 복구가 3회를 넘어서 무한 반복하지 않는지
5. 고1/고2/high12 제품으로 넘어가지 않는지
6. 새 전체 대시보드에서 공식자료와 진학사 예측이 분리 표시되는지
