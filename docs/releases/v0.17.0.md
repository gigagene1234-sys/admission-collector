# Admission Hub v0.17.0 — Server-Owned Jinhak Auth

## Why this release exists

Real Galaxy evidence from v0.16.9 showed that the Jinhak website session was already logged in while the Collector's DOM-based auth detector classified it as unauthenticated and sent the WebView back into login flow. The old Collector-owned authentication architecture is therefore retired for Jinhak.

## New Jinhak authentication model

- The Collector opens only actual protected high3 mission routes.
- The Collector does not decide whether the user is logged in by inspecting login/logout DOM controls.
- The Collector never constructs or programmatically opens a `member.jinhak.com` login URL.
- Generic/member login pages are allowed only when Jinhak itself navigates there.
- A site-owned login redirect pauses the active mission without changing its target.
- A natural return to a high3 route resumes the paused mission without a second auth probe.
- Lower-grade (`high1`, `high2`, `high12`) routes remain transport-blocked, but a lower-grade attempt is not allowed to terminate the whole batch.
- Collector-side Jinhak ID/PW storage, reading and auto-submission are disabled. Site login/Samsung Pass remains outside the Collector.

## Diagnostic acceptance fields

The v0.17.0 auth diagnostics expose:

- `jinhakAuthModel = server-owned-no-dom-probe-v0170`
- `forcedAuthNavigations` — must stay `0`
- `domAuthChecks` — must stay `0`
- `serverLoginRedirects`
- `naturalHigh3Returns`
- `protectedMissionStarts`

## Safety contracts retained

- Adiga remains the official current/historical source.
- Jinhak remains user-viewed derived analysis/prediction and is never promoted to official evidence.
- Prediction does not overwrite historical actuals.
- Credentials, cookies, session secrets and form values are not exported in diagnostic packages.
- `relation`, `probabilityInferred`, disclaimer, missing/warnings/risks safety semantics remain unchanged.

## Device acceptance

CI/build/signing success is not real-device login acceptance. v0.17.0 remains **DEVICE_AUTH_UNVERIFIED** until a Galaxy run demonstrates all of the following:

1. no Collector-generated navigation to `member.jinhak.com`;
2. `forcedAuthNavigations = 0` and `domAuthChecks = 0`;
3. no visible high1/high2/high12 page;
4. the protected high3 mission starts and at least one real mission action/identity is discovered;
5. Jinhak evidence for the selected applications increases beyond homepage-only snapshots;
6. no reauth-circuit terminal stop.

Do not uninstall the existing app before update-installing this APK; uninstalling may remove local Admission Hub data.
