# Admission Hub v0.13: 원서 적정성 검토 설계와 검토 결과

## 제품 목표와 범위

사용자가 선택한 수시 6장을 유지하면서 성적, 공식 과거 입결, 진학사 원자료, 지원조건과 일정을 함께 점검한다. 수집 종료, 핵심 자료 수집, 공식 연결, 성적 비교, 최종 합격 판단은 서로 다른 상태다. 데이터가 없는 칸을 0 또는 임의의 확률로 채우지 않는다.

이번 검토에서 기존 자료와 6장 선택의 지속성이 확인되었다. 파일명의 앱 버전과 기존 수집 세션 버전은 다를 수 있다. 이전 JSON에는 성적·판정 내보내기가 연결되지 않았고, 성적 집계가 선택 외 후보까지 포함할 수 있었다. 두 경로를 수정했다. 재수집에 앞서 기존 DB의 선택 카드 자료를 활용한다.

## 사용 흐름

1. Hub에서 내 성적 입력/가져오기를 연다. UTF-8 CSV, 엑셀에서 복사한 탭 구분 표 또는 성적 JSON을 입력한다.
2. 학년·학기·과목·등급·학점을 검토한다. 성취도만 있는 과목은 등급 빈칸으로 유지한다. 미기재 등급은 평균에 0으로 들어가지 않는다. 학점이 빠진 등급 과목이 있으면 가중평균을 보류한다.
3. 미리보기의 과목 수와 평균을 확인하고 저장한다. 이 평균은 입력된 과목의 평균이며 대학 공식 환산과 별개다.
4. 선택한 카드의 원서 적정성 화면에서 공식 환산값과 과거 입결을 출처, 산식 및 표의 해당 행과 함께 등록한다. 대학·모집단위·전형·연도·점수 척도·반영방법을 직접 확인한다.
5. 지원자격·수능최저·제출서류·복수지원 규칙과 마감시각을 해당 연도 공식 자료로 확인한다. 모의평가 결과를 실제 수능최저 확정 충족으로 취급하지 않는다.
6. 6장 전체 검토에서 각 원서의 근거, 부족한 자료, 성적 위험과 일정 확인 사항을 본다. 바꾸려는 지원안은 기존 6장 관리 기능에서 사용자가 직접 변경한다.

## 판단 계약

| 상태 | 적용 근거 | 의미 |
| --- | --- | --- |
| 자료 보완 후 판단 | 과목 입력, 현재 프로필, 공식 근거, 동일 척도 또는 지원조건 미확인 | 부족한 항목을 명시하고 비교/판단 보류 |
| 성적 위험 확인 | 확인한 과거 참고선보다 내 점수가 불리 | 과거 지표와의 비교이며 불합격 확정이 아님 |
| 지원조건·일정 재검토 | 미충족 조건으로 입력했거나 입력 마감시각 경과 | 원서 작성·접수 완료 여부와 조건 확인 필요 |
| 입력 근거상 지원 검토 가능 | 성적 비교가 가능하고 입력 조건·일정의 확인이 끝남 | 사용자 확인 자료에 따른 조건부 검토 결과. 합격확률이나 안정권 판정이 아님 |

종합·면접 전형에는 교과만으로 최종 결과를 판단할 수 없다는 한계를 함께 표시한다. 같은 대학 복수지원 및 같은 날짜 면접은 확인 항목이며 자동 불가능 판정이 아니다. 점수 차이에 임의의 안정/적정/소신 경계를 설정하지 않는다.

## 근거와 신뢰 경계

- 대학 자동 환산식 전체를 새로 추정하거나 구현한 버전이 아니다. 대학 공식 계산기·모집요강에서 확인한 값을 입력하고, 대학별 반영과목과 가산점을 확인하도록 연결했다.
- 사용자 확인 공식 자료는 `USER_REVIEWED_OFFICIAL_SOURCE`로 식별한다. 자동으로 독립 검증된 공식 환산 결과와 구분하며, 기존 verified 계층을 덮어쓰지 않는다.
- 공식 출처를 등록할 때 원문 URL 및 같은 전형/모집단위 행 근거를 요구한다. 대학 단위 Adiga 자료는 전체 학과의 공식 입결로 승격하지 않는다.
- 진학사 예측값은 기존 레코드의 동일 identity·연도와 한 카드 원문의 접두부(대학, 전형, 캠퍼스, 학과, 모집인원, 내 점수)를 재검증한다. 학과 DOM 표지가 누락되었다고 인접 카드에서 추측하지 않는다.
- 진학사 점수·칸수·반영등급·모의지원자 평균은 해당 제공자의 관측값이다. 확률로 변환하거나 공식 대학 환산값으로 인증하지 않는다.
- 과거 공식 지표는 평균, 70%컷, 100%컷 등 원래 지표명을 유지한다. 서로 다른 연도의 반영방식이 동일한지 확인한 근거가 필요하다.
- 성적 프로필의 내용 해시가 변경되면 기존 비교를 보류한다. 조건/메모 편집만으로 오래된 성적을 다시 승인하지 않는다.

공식 자료 확인 경로: [우송대 2027 모집요강](https://ent.wsu.ac.kr/board/read.jsp?code=einfo0601&id=267261), [우송대 성적산출](https://ent2.wsu.ac.kr/pass/susi02.php), [국립한밭대 2027 모집요강 공지](https://hanbat.ac.kr/prog/bbsArticle/BBSMSTR_000000000138/view.do?mno=sub05_02&nttId=B000000166895Ke0gF0r), [어디가](https://www.adiga.kr/). 공지·웹 계산기의 표시 연도가 혼재할 수 있으므로 실제 적용 연도를 확인한다.

## 저장·복구와 개인정보

SQLite v10은 원서별 검토 입력과 변경 이력을 추가한다. 이전 성적, 수집 레코드, 6장 슬롯을 지우지 않는다. 입력/내보내기에는 허용한 성적·원서 필드만 연결한다. 내보내는 앱 버전과 과거 수집 버전은 별도 필드다.

원래 v0.12 소스에는 인계된 정책과 달리 비밀번호 암호화 저장·자동 입력/제출 및 별도 쿠키 복사 기능이 있었다. 이 버전에서는 해당 저장본을 삭제하고 자동 입력/제출 경로를 제거한다. SQLite와 브라우저의 기본 쿠키 저장소를 초기화하지 않는다. 브라우저 기본 세션이 유효하면 이를 사용하고, 실제 인증이 필요하면 사용자가 로그인한다. 미션/렌더러 lease, auth proof, same-card, 선택 6장 소유권의 기존 코어 파일은 내용 해시를 고정해 회귀를 검사한다.

## 검증 및 남은 한계

기존 테스트와 성적 누락/중복/범위, 비교 방향, 학년도, 프로필 변경, 잘못된 카드 연결, 숫자 모순, 지원조건, 마감, 일정 충돌, JSON 내보내기 왕복 테스트를 함께 실행한다. 추가 테이블 마이그레이션은 기존 데이터가 있는 SQLite에서 반복 적용해 보존을 확인한다. 실제 APK의 버전·패키지·서명 확인과 커밋 기준 clean rebuild/retest 후에만 릴리스한다.

새 APK의 Galaxy Tab 화면·파일선택·실제 DB 업그레이드·로그인 만료 시 재개는 설치 후 확인한다. 공식 환산식의 자동 실행, Adiga 전형/학과별 수치 자동 추출의 전체 범위, 실제 수능 결과와 서류/면접 평가까지의 자동 검증은 이번 버전이 완료했다고 주장하지 않는다. 이 항목들이 없어도 출처를 확인한 입력으로 원서별 조건부 검토를 사용할 수 있다.
