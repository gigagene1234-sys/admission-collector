## Findings

### F1. Collection breadth improved, but exact rendered states were repeatedly expanded

Observation evidence showed exact-state repeats including:
- `www.jinhak.com/jh/high3/jinhak-tv`: seenCount 428 for one state
- `.../ipsi-analysis/ipsi-strategy`: seenCount 87
- `.../major-deep-analysis`: seenCount 38

Policy:
- repeated observations are not discarded;
- same route with changed context/content remains a new observation and is expandable;
- only outgoing-link expansion of the exact same `route + contextFingerprint + contentFingerprint` state is suppressed.

### F2. Route classification must precede broad text heuristics

v0.7.1 misclassified strategy/editorial pages containing the phrase `수능최저` as the dedicated SAT-minimum service.
That allowed page-wide generic inference to produce polluted rows, including numerical table-header tokens interpreted as grade values.

v0.8.0 policy:
- dedicated SAT minimum only from known dedicated routes;
- strategy, special-feature, media, deep-analysis/editorial receive separate page types;
- generic page-wide inference is allowed only on page types where its semantics are verified.

### F3. Observation preservation succeeded, but spreadsheet-ready normalization lagged behind

Full v0.7.1 analysis contained:
- 202 captured tables
- 334 captured blocks
- 357,050 captured text characters
- 0 text-budget exhaustion events

A conservative table-header scan found dozens of admission-relevant tables on zero-record pages. Examples included headers for competition, mock-support competition, predicted support cut, capacity, applicants, replenishment and 50/70 percent cuts.

v0.8.0 adds `jinhak-table-evidence`:
- explicit table cells are converted to row records;
- original columns and raw evidence are retained;
- university/department/admission stay null unless explicitly bound;
- no neighbor-card or page-wide guessing is introduced.

### F4. Error counts were not sufficient for the promised Excel Errors sheet

v0.7.1 exported aggregate error counts but not enough row-level document/page evidence.

v0.8.0 analysis-ready contract v2 streams:
- `errorEvidence.adiga`
- `errorEvidence.jinhak`
- `syncDiagnostics`

Each error row carries only safe path/family, state, error type, retry count and timestamp.

## Implemented v0.8.0 architecture retained from the pre-release base

- AndroidKeyStore + AES-GCM local session vault
- opaque session lease metadata; no password or browser session material sent to cloud
- Jinhak autonomous URL crawler
- safe read-only Jinhak browser agent for tabs/buttons/SPA state
- 35-second absolute Jinhak target watchdog
- WebView renderer recovery and runtime crash guard
- Observation Store with context/content-aware identity
- SQLite streaming unified export
- Cloudflare Worker 0.4.0 frontier batch/claim/complete
- D1 central frontier and public Adiga discovery

## v0.8.0 release stages

### Stage 1 — Session continuity
Goal: first login only when the Jinhak session is genuinely absent/expired.

Acceptance:
- update-install preserves local DB;
- authenticated session snapshot is protected by AndroidKeyStore;
- app restart attempts session restoration before presenting login;
- failed restoration falls back to normal user login without a collection reset.

### Stage 2 — Autonomous discovery + state agent
Goal: one collection start continues through Jinhak without page-by-page user navigation.

Acceptance:
- static internal links continue to be traversed;
- safe read-only SPA controls can be activated by the agent;
- payment/account/submission/destructive controls remain blocked;
- exact rendered state outgoing links are expanded once;
- changed content/context on the same URL remains eligible for capture and expansion.

### Stage 3 — Evidence-first normalization
Goal: increase useful records without reducing information capture.

Acceptance:
- observations remain authoritative evidence;
- relevant unknown tables may become `jinhak-table-evidence` rows;
- missing university/department/admission is never inferred from neighboring cards;
- historical actual/prediction/reference semantics remain separated.

### Stage 4 — Cloud frontier
Goal: move queue/dedupe/public discovery work away from the Android foreground process.

Acceptance:
- URL batches are published to Cloudflare frontier;
- D1 performs persistent task dedupe/lease/retry bookkeeping;
- public Adiga discovery can continue under Cloudflare cron;
- authenticated Jinhak rendering remains on-device; cookies/session tokens are never uploaded.

### Stage 5 — Analysis-ready export
Goal: the next run can be turned into a workbook/dashboard without reconstructing missing diagnostics.

Workbook target:
- Dashboard
- UnifiedRecords
- JinhakPredictions
- HistoricalResults
- Observations
- Coverage
- Errors

Export acceptance:
- analysisReady contractVersion 2
- full observation evidence retained
- row-level safe error evidence present
- crawl diagnostics present, including unique navigation expansion states and repeated-state skips
- prediction snapshots preserve `observedAt`

## v0.7.1 → v0.8.0 comparison gates for the next real-device run

Do not judge success by raw page count alone.

Primary gates:
1. no regression from Adiga 18,134-record baseline unless explained by deliberate authoritative-data update;
2. Jinhak autonomous run completes without manual page-by-page browsing;
3. no exact-state expansion loop comparable to v0.7.1's 428-repeat Jinhak-TV state;
4. `jinhak-sat-minimum` is no longer inflated by strategy/editorial articles;
5. no known page-wide pollution pattern such as table header `70%` becoming `grade=70`;
6. spreadsheet-ready Jinhak rows increase through explicit table evidence rather than unsafe inference;
7. department nulls remain null unless own-card/explicit context supports the binding;
8. `errorEvidence` accounts for unresolved/error documents sufficiently to diagnose failures;
9. Cloud frontier counters and Jinhak crawl diagnostics are exported;
10. unified JSON streaming finishes without OOM/crash.
